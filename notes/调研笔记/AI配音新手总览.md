# AI 配音新手总览

> 本文负责把 AI 配音从“模型和工具清单”还原成一个可理解的生产流程：它的目标是什么、输入输出是什么、为什么必须分成多个环节，以及新手应该先抓住哪些对象。

## 一句话理解

AI 配音不是单纯“把字幕丢给 TTS”，而是把翻译文本、说话人、音色参考、时间轴、背景声和视频封装组织成一条稳定流水线，最终生成一条新的目标语种配音视频。

## 输入和目标

本流程默认已经具备三类输入：

|输入|作用|
|---|---|
|源语种 SRT|提供原文、字幕序号和原始时间轴，是对齐与说话人归属的基础|
|翻译后 SRT|提供目标语种文本，后续需要做控长、断句和 TTS 适配|
|原始 MP4 视频|提供画面、原音轨、背景声、人声片段和最终封装容器|

最终目标不是生成一堆音频片段，而是生成一条新的 dubbed MP4：

```text
原视频画面
+ 背景音乐 / 环境声 / 音效
+ 目标语种 AI 配音
-> 最终配音视频
```

## 主流程骨架

可以先把 AI 配音理解成 9 个连续动作：

```text
源 SRT + 翻译 SRT + MP4
  -> 生成字幕任务表
  -> 说话人识别
  -> 翻译文本控长
  -> 人声 / 背景音分离
  -> 准备音色参考
  -> 音色克隆 TTS
  -> 音频时间轴对齐
  -> 背景混音
  -> 封装回 MP4
```

这条链路里最重要的不是某个单点模型，而是每一步都要把结果交给下一步。只要中间对象不清楚，后续就会变成一堆互相不兼容的音频、字幕和时间戳。

## 新手先抓住的核心对象

### `dubbing_tasks`

`dubbing_tasks` 是贯穿全流程的任务表。

不要把每一步都直接写回 SRT。SRT 只适合表达字幕文本和时间戳，不适合承载说话人、音色参考、TTS 输出、对齐结果和处理状态。

可以把 `dubbing_tasks` 理解成每条字幕的工作单：

```text
这一句是谁说的
原文是什么
目标语是什么
时间预算是多少
用哪个 reference audio
生成出的 TTS 音频在哪里
是否超时
是否需要改写或重生成
```

### `speaker_id`

`speaker_id` 表示“这条字幕属于哪个说话人”。

它不是音色文件，也不是 TTS 结果。它的作用是让后续 reference audio 能按角色聚合，而不是把所有台词都当成同一个人说。

### `reference_audio`

`reference_audio` 是给音色克隆 TTS 模仿声音用的参考音频。

它的关键要求不是越多越好，而是说话人一致、干净、长度合适。多人混杂、背景声太重、太短或噪声太多，都会污染后续音色。

### `tts_audio`

`tts_audio` 是目标语种配音片段。

它由 `target_text_adjusted` 和 `reference_audio` 生成，但它不会天然等于字幕时间槽。TTS 之后还要做时长检查、轻度变速、补静音或回到文本重新调整。

### `vocals` 和 `background`

从 MP4 音轨中通常要分出两类结果：

|对象|用途|
|---|---|
|`vocals.wav`|截取和清理说话人 reference audio，也可用于检测原人声时段|
|`background.wav`|保留背景音乐、环境声和音效，用于最终混音|

人声分离不是最终配音，只是为了拿到更干净的参考声音，并保留原视频的非人声音轨。

## 最容易混淆的边界

|容易混淆的对象|正确理解|
|---|---|
|翻译 SRT 与 TTS 文本|翻译 SRT 只是原始译文，TTS 前通常还需要控长和断句|
|说话人识别与音色克隆|说话人识别回答“谁说这句”，音色克隆回答“用什么声音生成这句”|
|reference audio 与 TTS audio|前者是模仿对象，后者是生成结果|
|人声分离与说话人识别|人声分离处理音轨 stem，说话人识别处理说话人归属|
|音频变速与时间轴对齐|变速只是对齐手段之一，严重超时应回到文本调整|
|AI 配音与 lip-sync|AI 配音先解决声音和时间轴，口型修复是更高要求的视频后处理|

## 为什么不能只靠 TTS

如果直接把翻译字幕逐条丢给 TTS，会遇到四类问题：

1. 翻译后的句子可能比原时间槽长，生成音频放不进去。
2. 多角色视频里，不同角色会被同一个声音覆盖。
3. 原视频背景音乐和环境声会丢失，最终成片像重新录音而不是配音。
4. 每条 TTS 片段独立生成，拼接后容易出现重叠、空隙、响度不一致和音色漂移。

所以 AI 配音的本质是一个时间轴工程、音频工程和生成模型工程的组合。
