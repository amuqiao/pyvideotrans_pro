这份 [AI 配音全流程调研报告.md](</Users/admin/Downloads/tmp/AI 配音全流程调研报告.md>) 讲的不是“找一个 TTS 工具读字幕”，而是 **把一条原视频改造成目标语种配音视频的完整生产线**。

可以先用一句话理解：

```text
原视频 + 原字幕 + 翻译字幕
    -> 识别谁在说话
    -> 准备每个人的参考音色
    -> 生成目标语言配音
    -> 对齐原视频时间轴
    -> 保留背景声并封装成新视频
```

**1. 整体像一条配音流水线**

```text
源 SRT          翻译 SRT             MP4 视频
  |                |                    |
  |                v                    v
  |          翻译文本控长          抽取音轨
  |                |                    |
  v                v                    v
说话人识别 ----> 任务表 <---- 人声 / 背景音分离
                    |
                    v
              准备 reference audio
                    |
                    v
              音色克隆 TTS
                    |
                    v
              时间轴对齐
                    |
                    v
              背景混音 + 视频封装
                    |
                    v
              最终配音 MP4
```

这里最核心的中间对象是 `dubbing_tasks`。它像一张“每句台词的生产单”，记录这一句是谁说的、文本是什么、时间槽多长、用哪个参考音色、生成出来的音频多长、是否需要重写或重生成。

**2. 为什么要先调整翻译 SRT**

翻译字幕不一定适合直接朗读。比如原视频某句只有 2 秒，但翻译后变成很长一句，TTS 读出来可能要 5 秒。

所以第一步要做的是：

```text
翻译字幕
  -> 控制长度
  -> 断句 / 合并
  -> 保留语义和口吻
  -> 让它更适合 TTS
```

重点不是重新翻译，而是让每句配音尽量放进原来的时间槽。

**3. 为什么要做人声分离**

原视频音轨里通常混在一起：

```text
原始音轨 = 原人声 + 背景音乐 + 环境声 + 音效
```

AI 配音希望替换“人声”，但保留背景音乐、环境声和音效。所以要分成：

```text
vocals.wav      -> 用来截取参考音色
background.wav  -> 最后和新配音混音
```

如果不做人声分离，最终视频可能会丢掉现场感，或者原人声和新配音混在一起。

**4. 为什么要识别说话人**

多角色视频不能所有台词都用同一个声音。

```text
字幕第 1 句 -> speaker_A
字幕第 2 句 -> speaker_B
字幕第 3 句 -> speaker_A
```

`speaker_id` 的作用就是告诉系统：这句是谁说的。后面准备 reference audio 和 TTS 时，才能让 A 继续像 A，B 继续像 B。

**5. Reference Audio 是什么**

`reference_audio` 是给音色克隆模型模仿的声音样本。

```text
某角色的干净原声片段
      +
目标语言文本
      ->
带这个角色音色的新配音
```

它不是越长越好。好的 reference audio 要满足：

```text
同一个人
声音干净
没有多人重叠
背景声少
长度适中
```

如果 reference 里混入其他人或背景音乐，生成出来的声音就容易漂。

**6. TTS 只是中间步骤，不是终点**

音色克隆 TTS 做的是：

```text
target_text_adjusted + reference_audio
    -> tts_audio
```

但 `tts_audio` 不会天然卡准视频时间。比如字幕时间槽是 2.5 秒，TTS 可能生成 2.1 秒，也可能生成 3.4 秒。

所以还要做对齐后处理：

```text
太短 -> 补静音
轻微太长 -> 轻度变速
严重太长 -> 回到文本，缩短后重生成
```

报告特别强调：不要把所有问题都交给变速。大幅变速会明显损伤自然度。

**7. 最后如何合成视频**

最终音频大概是：

```text
最终音频 = 对齐后的 AI 配音 + background.wav
```

然后再封装回原 MP4：

```text
原视频画面 + 最终音频 -> dubbed MP4
```

如果配音总时长比视频长，轻微情况可以延长尾帧；严重情况应该回到文本控长或 TTS 重生成。

**8. 这份报告最重要的判断**

它真正想表达的是：

```text
AI 配音不是单点模型能力
而是一套围绕时间轴运转的工程流程
```

最容易出问题的地方也很清楚：

```text
翻译太长       -> TTS 放不进时间槽
人声分离不干净 -> reference 被污染
说话人识别错   -> 角色声音混乱
reference 太短 -> 音色逐句漂移
TTS 不对齐     -> 配音和画面节奏错位
过度变速       -> 声音不自然
```

所以读这份报告时，不要先陷进模型名。先抓住这条主线：

```text
文本适配
  -> 声音来源
  -> 角色归属
  -> 音色生成
  -> 时间对齐
  -> 混音封装
```

只要这条线清楚，Demucs、pyannote、F5-TTS、CosyVoice、ElevenLabs、WhisperX、FFmpeg 这些工具就都能放回各自的位置。
