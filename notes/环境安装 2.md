完整方案按是否需要 `MOSS-TTS` 分两条线。

**方案 A：推荐，先跑起来，不装 MOSS-TTS**

你的报错只来自 `mosstts -> pynini`。如果暂时不用 `MOSS-TTS-Nano`，直接排除它：

```bash
uv sync --all-extras --no-extra mosstts --default-index https://mirrors.aliyun.com/pypi/simple/
```

然后验证：

```bash
uv run python -c "import videotrans; print('ok')"
uv run sp.py
```

以后不要再执行纯 `uv sync --all-extras`，否则又会把 `mosstts` 拉进来。

**方案 B：必须使用 MOSS-TTS**

先尝试把 `pynini` 从锁文件里的 `2.1.6` 升到更新版本：

```bash
uv lock --upgrade-package pynini --default-index https://mirrors.aliyun.com/pypi/simple/
uv sync --extra mosstts --default-index https://mirrors.aliyun.com/pypi/simple/
```

如果成功，再装其他 extras 时继续排除 `mosstts`，避免重复触发：

```bash
uv sync --all-extras --no-extra mosstts --default-index https://mirrors.aliyun.com/pypi/simple/
```

如果方案 B 仍失败，macOS arm64 上建议不要用 PyPI 源码编译 `pynini`，改用 conda-forge 预编译包。也就是说，用 conda/micromamba 创建 Python 3.10 环境并安装 `pynini`，再让项目在该环境里运行。这比折腾 Homebrew `openfst` 头文件兼容更稳。

当前你的情况我建议执行：

```bash
uv sync --all-extras --no-extra mosstts --default-index https://mirrors.aliyun.com/pypi/simple/
```

这能绕过 `pynini` 编译错误，同时保留除 `MOSS-TTS` 外的其他可选功能。
