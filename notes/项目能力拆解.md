# pyVideoTrans 项目能力拆解

本文基于当前源码拆解 pyVideoTrans 的真实能力边界：它不是单个 AI 模型，而是一个用任务配置、文件中间产物和多类 provider 串起来的媒体翻译与配音编排器。

## 1. 文档职责

本文负责回答：

- 项目有哪些单模块能力，例如语音识别、字幕翻译、字幕配音、媒体处理。
- 项目有哪些串联能力，例如完整视频翻译、配音、字幕嵌入和最终 MP4 合成。
- 每个能力的输入、输出、实现路径、技术栈和源码位置。
- 哪些能力是主流程，哪些能力是条件分支或可选增强。
- 当前项目对“单个原始 MP4 + 目标语种 -> 目标语种配音 MP4”的支持程度。

本文不负责：

- 逐个展开所有云服务和本地模型的私有参数。
- 替代安装文档、渠道账号配置文档或完整 API 合同文档。
- 承诺所有 provider 开箱即用；很多渠道依赖模型下载、外部服务、API Key 或平台环境。

## 2. 总心智模型

先把项目理解成五层，而不是一个大脚本：

```text
入口层
  桌面 GUI / CLI / WebUI
  负责收集用户选择，把它们整理成任务参数

运行时底座
  全局配置 / 队列 / 信号 / 日志 / 缓存目录
  负责让 GUI、CLI、WebUI 共用同一套任务环境

任务编排层
  TaskCfg* + BaseTask + TransCreate / SpeechToText / TranslateSrt / DubbingSrt
  负责决定哪些阶段要跑、哪些阶段跳过、每一步读写哪些文件

provider 适配层
  recognition / translator / tts
  负责把统一输入转给不同 ASR、翻译、TTS 渠道

媒体与模型工具层
  FFmpeg / ffprobe / PyTorch / ONNX / CTranslate2 / pydub / rubberband
  负责真实的音视频拆分、转码、识别、合成、变速和混流
```

最重要的一点是：**任务不是靠一个内存对象一路传到底，而是靠配置对象和一批文件产物推进。**

```text
TaskCfgVTT
  -> 计算 source_sub / target_sub / source_wav / target_wav / novoice_mp4 / targetdir_mp4
  -> 按 should_recogn / should_trans / should_dubbing / should_hebing 裁剪流程
  -> 每个阶段读上一步文件，写下一步文件
  -> 最后合成视频或输出字幕/音频
```

## 3. 不同模块的心智模型

### 3.1 入口层心智模型

入口层不是业务内核。它只负责把用户输入变成任务配置。

```text
用户操作或命令参数
  -> 解析语言、渠道、音色、字幕类型、输出目录
  -> 生成 TaskCfgSTT / TaskCfgSTS / TaskCfgTTS / TaskCfgVTT
  -> 交给任务类执行
```

源码定位：

- CLI 入口：[../cli.py](../cli.py)
- 桌面入口：[../sp.py](../sp.py)
- WebUI 入口：[../webui.py](../webui.py)
- 桌面主窗口：[../videotrans/mainwin/main_win.py](../videotrans/mainwin/main_win.py)

### 3.2 运行时底座心智模型

运行时底座是全局状态中心。它保存设置、队列、停止标记、GPU 信息、日志和信号通道。

```text
AppCfg
  -> prepare_queue / regcon_queue / trans_queue / dubb_queue / align_queue / assemb_queue
  -> stopped uuid / exit flag / codec cache / runtime settings
  -> GUI worker 和任务对象共同读写
```

源码定位：

- 全局配置：[../videotrans/configure/config.py](../videotrans/configure/config.py)
- 任务 worker：[../videotrans/task/job.py](../videotrans/task/job.py)

### 3.3 任务编排层心智模型

任务编排层是项目内核。它不直接代表某个模型，而是决定“该跑哪些阶段”。

```text
BaseTask
  定义 prepare / recogn / diariz / trans / dubbing / align / assembling / task_done

TransCreate
  完整视频翻译任务
  初始化时计算 should_* 分支
  执行时按阶段读写文件产物
```

源码定位：

- 任务配置：[../videotrans/task/taskcfg.py](../videotrans/task/taskcfg.py)
- 任务基类：[../videotrans/task/_base.py](../videotrans/task/_base.py)
- 完整视频任务：[../videotrans/task/trans_create.py](../videotrans/task/trans_create.py)

### 3.4 provider 适配层心智模型

ASR、翻译、TTS 都是 provider 家族。项目用统一入口和动态加载机制调用具体渠道。

```text
channel id
  -> ChannelProvider(name, imp, key_name, win)
  -> get_class()
  -> videotrans.recognition / translator / tts 下的具体实现类
  -> .run()
```

源码定位：

- 动态加载：[../videotrans/__init__.py](../videotrans/__init__.py)
- 识别渠道：[../videotrans/recognition/__init__.py](../videotrans/recognition/__init__.py)
- 翻译渠道：[../videotrans/translator/__init__.py](../videotrans/translator/__init__.py)
- 配音渠道：[../videotrans/tts/__init__.py](../videotrans/tts/__init__.py)

### 3.5 媒体处理层心智模型

媒体处理层负责“把模型输出放回视频里”。很多最终效果不是 AI provider 完成的，而是 FFmpeg 和音频处理完成的。

```text
原始 MP4
  -> ffprobe 读取媒体信息
  -> ffmpeg 拆无声视频和音频
  -> 可选人声/背景声分离
  -> 配音音频拼接、变速、补静音
  -> 字幕硬嵌或软嵌
  -> ffmpeg 合成 MP4 / MKV
```

源码定位：

- FFmpeg 工具：[../videotrans/util/help_ffmpeg.py](../videotrans/util/help_ffmpeg.py)
- 音频预处理与分离：[../videotrans/process/prepare_audio.py](../videotrans/process/prepare_audio.py)
- 配音与视频对齐：[../videotrans/task/_rate.py](../videotrans/task/_rate.py)

## 4. 核心数据对象

| 对象 | 所在源码 | 作用 |
|---|---|---|
| `TaskCfgBase` | [../videotrans/task/taskcfg.py](../videotrans/task/taskcfg.py) | 输入文件、输出目录、语言、音频/字幕路径等通用字段 |
| `TaskCfgSTT` | [../videotrans/task/taskcfg.py](../videotrans/task/taskcfg.py) | 语音识别参数，例如渠道、模型、CUDA、降噪、说话人数量 |
| `TaskCfgSTS` | [../videotrans/task/taskcfg.py](../videotrans/task/taskcfg.py) | 字幕翻译参数，例如翻译渠道 |
| `TaskCfgTTS` | [../videotrans/task/taskcfg.py](../videotrans/task/taskcfg.py) | 配音参数，例如 TTS 渠道、音色、语速、音量、音调 |
| `TaskCfgVTT` | [../videotrans/task/taskcfg.py](../videotrans/task/taskcfg.py) | 完整视频翻译参数，组合 STT、STS、TTS 和视频合成配置 |
| `SrtItem` | [../videotrans/task/taskcfg.py](../videotrans/task/taskcfg.py) | 一条字幕，包含行号、时间轴、文本、说话人、音频片段路径 |
| `queue_tts` | [../videotrans/task/trans_create.py](../videotrans/task/trans_create.py) | 配音任务队列，每条字幕对应一条待生成音频任务 |
| `source_sub` | `TaskCfgVTT` 运行时路径 | 原语言 SRT |
| `target_sub` | `TaskCfgVTT` 运行时路径 | 目标语言 SRT |
| `source_wav` | `TaskCfgVTT` 运行时路径 | 识别用 16k 单声道源音频 |
| `target_wav` | `TaskCfgVTT` 运行时路径 | 对齐后的目标语言配音音频 |
| `novoice_mp4` | `TaskCfgVTT` 运行时路径 | 去掉原音频的视频流 |
| `vocal` / `instrument` | `TaskCfgVTT` 运行时路径 | 人声和背景声分离结果 |
| `targetdir_mp4` | `TaskCfgVTT` 运行时路径 | 默认 MP4 输出基准路径；实际成片扩展名还会受 `out_video_ext` 设置影响 |

## 5. 能力总览

| 能力类型 | 能力 | 入口 | 典型输入 | 典型输出 |
|---|---|---|---|---|
| 单模块 | 语音识别 STT | `cli.py --task stt` / GUI | 音频或视频 | SRT 字幕 |
| 单模块 | 字幕翻译 STS | `cli.py --task sts` / GUI | SRT + 目标语言 | 翻译后 SRT |
| 单模块 | 字幕配音 TTS | `cli.py --task tts` / GUI | SRT/TXT + 音色 | WAV/MP3 音频 |
| 串联能力 | 完整视频翻译 VTV | `cli.py --task vtv` / GUI / WebUI | MP4 + 源语言 + 目标语言 + 可选音色 | 字幕、配音音频、最终视频 |
| 分支能力 | 只翻译字幕不配音 | VTV 中 `voice_role=No` | MP4 + 源/目标语言 | 翻译字幕和带字幕视频 |
| 分支能力 | 同语种重配音 | VTV 中源语言等于目标语言且有音色 | MP4 + 同一语言 + 音色 | 新配音视频 |
| 分支能力 | 人声/背景声分离 | `is_separate=True` | 含音轨媒体 | `vocal.wav` / `instrument.wav` |
| 分支能力 | 二次识别 | `recogn2pass=True` 且满足条件 | 配音后的目标音频 | 更贴近配音音频的目标字幕 |
| 分支能力 | 硬字幕/软字幕/双语字幕 | `subtitle_type` | 目标字幕和源字幕 | 嵌入字幕的视频 |

## 6. 入口能力拆解

### 6.1 CLI

CLI 是最清晰的自动化入口。它支持四类任务：

| 任务 | 对应类 | 输入 | 输出 | 执行方式 |
|---|---|---|---|---|
| `stt` | `SpeechToText` | 音频/视频、识别渠道、语言、模型 | SRT | 顺序执行 `prepare -> recogn -> diariz -> task_done` |
| `sts` | `TranslateSrt` | SRT、源语言、目标语言、翻译渠道 | 目标语言 SRT | 顺序执行 `trans -> task_done` |
| `tts` | `DubbingSrt` | SRT/TXT、TTS 渠道、音色、语速等 | WAV 或指定音频格式 | 顺序执行 `dubbing -> align -> task_done` |
| `vtv` | `TransCreate` | 视频/音频、源语言、目标语言、识别/翻译/TTS/合成参数 | 字幕、音频、最终视频 | 顺序执行完整阶段 |

CLI 源码定位：[../cli.py](../cli.py)

注意：当前 `vtv` 在 CLI 校验中要求 `--source_language_code` 和 `--target_language_code` 都存在。它不是“只传目标语言就自动完成”的接口。

### 6.2 桌面 GUI

桌面 GUI 是完整功能入口。它加载主窗口、配置窗口、渠道设置窗口，并启动 worker 队列。

```text
MainWindow
  -> 用户选择文件、语言、渠道、配音角色、字幕类型
  -> 生成 TaskCfgVTT
  -> 单视频交互或批量任务
  -> prepare_queue
  -> 各阶段 worker 按 should_* 路由
```

源码定位：

- 启动：[../sp.py](../sp.py)
- 主窗口：[../videotrans/mainwin/main_win.py](../videotrans/mainwin/main_win.py)
- 动作收集：[../videotrans/mainwin/_actions.py](../videotrans/mainwin/_actions.py)
- worker 队列：[../videotrans/task/job.py](../videotrans/task/job.py)

### 6.3 WebUI

WebUI 是简化入口，使用 Gradio 提供视频/音频翻译表单。它不是桌面端的完整替代。

```text
Gradio 表单
  -> 限定可选识别/翻译/TTS 渠道
  -> 构造 TaskCfgVTT
  -> 同步调用 TransCreate 的各阶段
  -> 返回视频预览和输出文件
```

源码定位：[../webui.py](../webui.py)

WebUI 当前显式说明“仅实现部分功能，完整功能请使用桌面软件版”。它适合跑通集中流程，不适合覆盖所有高级设置窗口和所有渠道配置。

## 7. 单模块能力

### 7.1 语音识别模块

模块心智模型：

```text
音频文件
  -> 规范为 16k 单声道 WAV
  -> ASR provider
  -> SrtItem 列表
  -> SRT 文件
```

单模块入口：

- CLI：`uv run cli.py --task stt --name input.mp4`
- 任务类：[../videotrans/task/speech2text.py](../videotrans/task/speech2text.py)
- provider 入口：[../videotrans/recognition/__init__.py](../videotrans/recognition/__init__.py)

输入：

- 音频或视频文件。
- `recogn_type`：识别渠道。
- `detect_language`：发音语言，部分渠道支持 `auto`。
- `model_name`：模型名称。
- `is_cuda`：是否使用 CUDA。
- 可选：降噪、说话人分离、LLM 重新断句、标点处理。

输出：

- 标准字幕 `SRT`。
- 内部结构是 `List[SrtItem]`。
- 可选说话人结果是运行时内部产物；独立 STT 流程不会稳定交付 `speaker.json` 到输出目录。

主要技术栈：

- FFmpeg：抽取并转成识别用 WAV。
- faster-whisper / openai-whisper / FunASR / Qwen ASR / WhisperX / Deepgram / Gemini / 自定义 API 等。
- PyTorch、CTranslate2、Transformers、HuggingFace、ModelScope、ONNXRuntime。

能力边界：

- 渠道出现在列表里不代表开箱可用，部分需要 API Key、外部服务或模型下载。
- 自动识别语言不是所有 ASR 渠道都支持。
- 说话人分离是增强能力，不是识别成功的硬依赖。

### 7.2 字幕翻译模块

模块心智模型：

```text
源 SRT
  -> 解析为 SrtItem 列表
  -> 翻译 provider
  -> 对齐源字幕时间轴
  -> 写出目标 SRT
```

单模块入口：

- CLI：`uv run cli.py --task sts --name source.srt --target_language_code en`
- 任务类：[../videotrans/task/translate_srt.py](../videotrans/task/translate_srt.py)
- provider 入口：[../videotrans/translator/__init__.py](../videotrans/translator/__init__.py)

输入：

- 源 SRT。
- `source_language_code`，未传时 CLI 默认 `auto`。
- `target_language_code`。
- `translate_type`。

输出：

- 目标语言 SRT。
- 可选双语字幕格式。

主要技术栈：

- Google、Microsoft、M2M100。
- ChatGPT、DeepSeek、Gemini、Zhipu、AzureGPT、Local LLM、OpenRouter、QwenMT、VolcEngine、MiniMax、XiaoMi、CAMB。
- Tencent、Baidu、DeepL、DeepLx、Alibaba、LibreTranslate、自定义 API。

能力边界：

- 翻译 provider 还负责语言码映射、可用性判断、缓存和 AI/非 AI 分批策略。
- 翻译输出行数可能和源字幕不同，任务层会用源时间轴重新对齐目标文本。
- 不是所有语言和所有渠道都互相兼容。

### 7.3 字幕配音模块

模块心智模型：

```text
目标语言 SRT 或 TXT
  -> queue_tts
  -> TTS provider 生成分段音频
  -> 拼接、对齐、调音量
  -> 输出完整配音音频
```

单模块入口：

- CLI：`uv run cli.py --task tts --name target.srt --voice_role "en-US-GuyNeural"`
- 任务类：[../videotrans/task/dubbing.py](../videotrans/task/dubbing.py)
- provider 入口：[../videotrans/tts/__init__.py](../videotrans/tts/__init__.py)

输入：

- SRT 或 TXT。
- `tts_type`：配音渠道。
- `voice_role`：音色。
- `target_language_code`。
- 可选：语速、音量、音调、音频自动加速。

输出：

- 完整配音音频，默认 WAV。
- 可选保存每条字幕的分段音频。

主要技术栈：

- Edge-TTS、Qwen3 local、MOSS、Piper、VITS、ChatterBox。
- GPT-SoVITS、F5-TTS、Index-TTS、CosyVoice、VoxCPM、ChatTTS、Spark-TTS、Dia-TTS、Kokoro、clone-voice、Fish-TTS。
- OpenAI、Gemini、ElevenLabs、Azure、gTTS、自定义 API。
- pydub、FFmpeg、音频拼接和变速工具。

能力边界：

- TTS provider 只负责生成片段或单条音频；“和视频对齐”主要在任务层完成。
- `voice_role=clone` 只有在 `SUPPORT_CLONE` 标记的渠道中才有意义。
- TXT 配音和 SRT 配音的对齐语义不同：TXT 缺少真实时间轴，更多是顺序朗读。

### 7.4 媒体处理模块

模块心智模型：

```text
媒体文件
  -> 探测元信息
  -> 拆视频流 / 音频流
  -> 转码 / 拼接 / 变速 / 静音处理
  -> 字幕硬嵌或软嵌
  -> 输出最终媒体
```

入口：

- 工具函数：[../videotrans/util/help_ffmpeg.py](../videotrans/util/help_ffmpeg.py)
- 视频任务中调用：[../videotrans/task/trans_create.py](../videotrans/task/trans_create.py)
- 对齐实现：[../videotrans/task/_rate.py](../videotrans/task/_rate.py)

输入：

- 视频、音频、字幕、目标路径。
- 输出编码、字幕类型、是否硬件加速、是否慢速视频等设置。

输出：

- `novoice.mp4`。
- 识别用 WAV。
- 配音后 M4A/WAV。
- 硬字幕或软字幕视频。
- 最终 MP4/MKV。

主要技术栈：

- FFmpeg / ffprobe。
- H.264/H.265 硬件编码探测，按平台选择 videotoolbox、nvenc、qsv、amf、vaapi 或软件编码。
- pydub、soundfile、numpy、pyrubberband。

能力边界：

- FFmpeg 和 ffprobe 必须可执行。
- 硬字幕会触发视频重编码；软字幕或无字幕在满足条件时可以复制视频流。
- 配音比视频长时，项目可能选择音频加速、视频慢速或末尾定格，取决于配置。

### 7.5 人声/背景声分离与说话人能力

模块心智模型：

```text
源音频
  -> 人声/背景声分离
  -> vocal.wav 用于识别和克隆参考
  -> instrument.wav 用于最终重新混入背景

字幕时间轴 + 源音频
  -> diarization
  -> speaker.json
```

入口：

- 人声/背景声分离：[../videotrans/process/prepare_audio.py](../videotrans/process/prepare_audio.py)
- 说话人分离：[../videotrans/task/trans_create.py](../videotrans/task/trans_create.py)
- 独立分离 worker：[../videotrans/task/separate_worker.py](../videotrans/task/separate_worker.py)

输入：

- 原始音频或视频。
- `is_separate`。
- `enable_diariz`、`nums_diariz`。
- `speaker_type` 和可选 HuggingFace token。

输出：

- `vocal.wav`。
- `instrument.wav`。
- `speaker.json`。

主要技术栈：

- sherpa-onnx UVR / spleeter 风格模型。
- 内置 ONNX 说话人模型。
- Ali CAM。
- pyannote.audio。
- Reverb diarization。

能力边界：

- 人声/背景声分离失败时，主流程可能继续，但不会得到高质量背景重嵌或克隆参考。
- 说话人分离不是角色绑定，它只输出匿名 speaker 信息。
- 当前项目没有把“角色名、人工确认、reference 质量报告”产品化成统一主工单。

## 8. 完整视频翻译串联能力

完整视频翻译由 `TransCreate` 承担。它的心智模型是：

```text
输入媒体 + 任务配置
  -> 初始化路径和 should_* 分支
  -> 预处理媒体
  -> 识别源字幕
  -> 可选说话人分离
  -> 翻译目标字幕
  -> 可选生成目标配音
  -> 可选音画字幕对齐
  -> 可选二次识别
  -> 合成视频
  -> 收尾清理
```

源码定位：[../videotrans/task/trans_create.py](../videotrans/task/trans_create.py)

### 8.1 阶段表

| 阶段 | 输入 | 输出 | 如何实现 | 是否必跑 |
|---|---|---|---|---|
| 初始化 | `TaskCfgVTT` | 所有运行时路径和 `should_*` 标志 | `__post_init__` 计算路径、语言、分支 | 是 |
| `prepare` | 原始媒体、可选已有字幕、可选已有 `vocal/instrument` | `novoice.mp4`、`source_wav`、视频信息、可选人声/背景声 | FFmpeg 拆流，必要时做人声背景分离 | 是 |
| `recogn` | `source_wav` 或已有 `source_sub` | 原语言 SRT、`source_srt_list` | 调 `recognition.run()`，可选降噪、标点、LLM 断句 | 通常是，已有字幕时可跳过识别 |
| `diariz` | 源音频和字幕时间轴 | `speaker.json` | 内置模型、Ali CAM、pyannote 或 reverb | 可选 |
| `trans` | 原语言 SRT、源/目标语言、翻译渠道 | 目标语言 SRT | 调 `translator.run()`，对齐字幕行 | 源语言不同于目标语言时 |
| `dubbing` | 目标 SRT、源 SRT、TTS 配置 | `queue_tts`、分段配音音频 | 构造句级 TTS 任务，调 `tts.run()` | 有有效 `voice_role` 时 |
| `align` | 分段配音音频、字幕时间轴、无声视频 | `target_wav`、可选重写目标字幕、可选慢速视频 | `SpeedRate` 拼接、加速、补静音、慢速视频 | 配音时 |
| `recogn2pass` | 配音后的目标音频 | 覆盖后的目标字幕 | 对目标配音音频再做 ASR | 满足二次识别条件时 |
| `assembling` | 无声视频、目标音频、字幕 | 最终 MP4/MKV、目标音频输出 | FFmpeg 混流、硬字幕滤镜或软字幕流 | 需要合成时 |
| `task_done` | 阶段产物 | 成功信号、可选清理缓存 | 复制/移动最终产物，标记结束 | 是 |

### 8.2 典型完整流程

```bash
uv run cli.py --task vtv \
  --name "input.mp4" \
  --source_language_code zh-cn \
  --target_language_code en \
  --voice_role "en-US-GuyNeural"
```

实际链路：

```text
input.mp4
  -> cache/novoice.mp4
  -> cache/zh-cn.wav
  -> output/zh-cn.srt
  -> output/en.srt
  -> cache/dubb-*.wav
  -> cache/target.wav
  -> output/en.m4a
  -> output/input.mp4
```

如果开启 `--is_separate`：

```text
source audio
  -> vocal.wav       用于 ASR 和 clone reference
  -> instrument.wav  用于最终重新混入背景音
```

如果开启 `--recogn2pass` 且满足条件：

```text
target.wav
  -> 二次 ASR
  -> 覆盖 target_sub
```

## 9. 分支能力矩阵

| 分支 | 触发条件 | 跑哪些阶段 | 主要输出 | 注意点 |
|---|---|---|---|---|
| 标准视频翻译 + 配音 | 源语言 != 目标语言，且 `voice_role != No` | 全链路 | 目标字幕、目标音频、最终视频 | 最接近“翻译配音视频” |
| 只翻译并嵌字幕 | `voice_role=No`，`subtitle_type>0` | prepare、recogn、trans、assembling | 目标字幕、带字幕视频 | 不生成目标配音 |
| 只转录/翻译字幕 | `app_mode=tiqu` | prepare、recogn、trans、task_done | SRT | 不配音，不合成视频 |
| 同语种重配音 | 源语言 == 目标语言，且 `voice_role != No` | prepare、recogn、dubbing、align、assembling | 同语种新配音视频 | 不需要翻译 |
| 音频翻译 | 输入扩展名属于音频 | prepare、recogn、trans、dubbing、align、task_done | WAV 和字幕 | 不合成 MP4 |
| 人声背景分离 | `is_separate=True` | prepare 中增加分离 | `vocal.wav`、`instrument.wav` | 失败会降低增强能力 |
| 二次识别 | `recogn2pass=True`、有配音、非双语字幕、源/目标语言不同 | recogn2pass | 更贴近配音音频的目标字幕 | 双语字幕场景不生效 |
| 硬字幕 | `subtitle_type=1/3` | assembling 硬字幕滤镜 | 重编码视频 | 字幕烧录进画面 |
| 软字幕 | `subtitle_type=2/4` | assembling 字幕流 | 可开关字幕的视频 | MP4 使用 `mov_text` |
| 批量任务 | GUI 批量或 `mult_video.py` | worker 队列 | 多个输出目录 | 翻译和配音 worker 并发较保守 |

## 10. 执行模型差异

同一任务内核在不同入口下有不同执行模型。

| 入口 | 执行模型 | 特点 |
|---|---|---|
| CLI | 顺序调用 | 最适合自动化和批处理脚本，错误直接抛出 |
| WebUI | 顺序调用 | 页面内同步展示阶段日志，功能比桌面端少 |
| 桌面 GUI 单视频 | 可交互任务 | 更适合人工编辑字幕、选择角色、调整配置 |
| 桌面 GUI 批量 | 队列 worker | `prepare/regcon/diariz/trans/dubb/align/assemb/taskdone` 分阶段排队 |

GUI worker 路由模型：

```text
prepare_queue
  -> WorkerPrepare
  -> regcon_queue / trans_queue / dubb_queue / assemb_queue / taskdone_queue

regcon_queue
  -> WorkerRegcon
  -> diariz_queue

diariz_queue
  -> WorkerDiariz
  -> trans_queue / dubb_queue / assemb_queue / taskdone_queue

trans_queue
  -> WorkerTrans
  -> dubb_queue / assemb_queue / taskdone_queue

dubb_queue
  -> WorkerDubb
  -> align_queue

align_queue
  -> WorkerAlign
  -> regcon2_queue / assemb_queue / taskdone_queue

regcon2_queue
  -> WorkerRegcon2Pass
  -> assemb_queue / taskdone_queue

assemb_queue
  -> WorkerAssemb
  -> taskdone_queue
```

源码定位：[../videotrans/task/job.py](../videotrans/task/job.py)

## 12. 当前能力边界

### 12.1 已实现的能力

- 单独做语音识别，输出 SRT。
- 单独翻译字幕，输出目标语言 SRT。
- 单独给字幕或文本配音，输出音频。
- 对单个视频执行完整识别、翻译、配音、对齐、字幕嵌入和最终合成。
- 可选人声/背景声分离。
- 可选说话人分离。
- 可选二次识别配音音频。
- 支持硬字幕、软字幕、双语硬字幕、双语软字幕。
- 支持音频输入，输出目标语言音频和字幕。
- 支持多个 ASR、翻译、TTS provider 动态扩展。

### 12.2 部分支持或需要条件的能力

- “声音克隆”是组合能力：任务层裁切参考音频，TTS provider 负责合成，并且必须选择支持 clone 的渠道。
- “说话人识别”不是角色绑定，源码没有完整的角色人工审核和 reference 质量报告闭环。
- WebUI 是简化入口，不能覆盖桌面端所有渠道配置和高级窗口。
- 云渠道需要 API Key，本地 API 渠道需要外部服务，本地模型渠道可能需要下载模型和额外依赖。
- 自动语言识别只在部分 ASR 渠道可靠或可用。

### 12.3 当前不等同于完整产品化流程的部分

调研笔记里定义的“单 MP4 输入工程流程”包含：

```text
原始 MP4 + 目标语种
  -> 全链路报告
  -> 可追溯句级任务表
  -> speaker profile
  -> reference audio 质量报告
  -> QA 报告和返工入口
```

当前源码有主干媒体翻译配音能力，但没有把这些产物统一成稳定的 `tasks/dubbing_tasks.json` 主工单，也没有完整的 QA 报告、人工审核和返工闭环。

## 13. 对“单个原始 MP4 + 目标语种 -> 目标语种配音 MP4”的支持判断

严格两输入版本：

```text
输入：原始 MP4 + 目标语种
输出：目标语种配音 MP4
```

当前项目 **不完全支持**，因为 CLI 的 `vtv` 当前要求显式传 `source_language_code` 和 `target_language_code`，配音还需要指定有效 `voice_role`。如果不指定音色，默认不会配音。

这个限制不是单纯的 CLI 约束。桌面 GUI 和 WebUI 的任务配置同样围绕“源语言、目标语言、配音角色”组织；没有有效源语言时无法稳定完成识别/翻译链路，没有有效配音角色时不会进入配音阶段。

当前可用版本是：

```text
输入：原始 MP4 + 源语言 + 目标语种 + 配音角色
输出：目标语种配音 MP4 + 目标字幕 + 目标音频
```

示例：

```bash
uv run cli.py --task vtv \
  --name "input.mp4" \
  --source_language_code zh-cn \
  --target_language_code en \
  --voice_role "en-US-GuyNeural"
```

如果要把项目改造成严格“两输入流程”，至少需要补齐：

- 源语言自动检测后的稳定写回。
- 默认目标语言音色选择策略。
- 无音色时不能默认为 `No`，否则不会生成配音。
- 任务报告和句级任务表。
- 失败阶段、返工阶段和人工复核状态。
